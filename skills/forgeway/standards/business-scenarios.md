## Applicability and authority

本标准持有跨项目的业务场景默认要求。项目 Product 持有具体行为和例外，API/Data/UI/source
分别持有自己的合同与实现；本标准不复制它们，也不产生新的项目状态账或业务 schema。

- 新建或本次明确授权调整的业务列表 MUST 默认包含分页、排序、搜索和详情；涉及状态的
  操作 MUST 定义状态、动作、角色和数据范围的关系。适用行为进入当前 Feature 的验收项。
- Product owner MUST 将受影响场景判为 `applicable`、`not-applicable` 或 `Open`，引用
  已确认的决定；例外 MUST 给出场景、理由、替代行为及对应验收。没有记录不能当作豁免。
- 选择器、固定且有界的枚举、汇总图表可能无需完整列表能力；这只是例外候选，不是自动豁免。
  表单或 CLI 等不含业务列表的切片，不因加载本标准就获得列表/UI 要求。
- 已有项目 MUST 保留已接受行为；采用本标准不是批量补页面、按钮、文案、接口或改造后端的
  授权。发现差距回到原 owner，只有依赖该差距的切片暂停，其余授权工作继续。
- 标准采用与目标项目运行符合性 MUST 分开。引用文件、模板填写和静态检查都不能证明业务已实现。

## Lists and queries

| 关注点 | 默认要求与验收边界 |
| --- | --- |
| 分页 | MUST 明确分页方式、容量上限、首尾页与空页行为；复用项目分页参数和返回结构。页码/游标选择由 API owner 决定；游标列表不伪造页数或总数。未采用项目合同的全量下载再截取不能代替后端分页。 |
| 排序 | MUST 有明确默认顺序和可用排序字段；后端白名单映射字段与方向，以唯一键消除相同排序值的歧义。分页后的局部排序不能冒充全结果排序；动态集合还需按业务要求定义快照或游标一致性。 |
| 搜索和筛选 | MUST 明确可搜索字段、匹配语义、组合条件、空值与重置行为；搜索/筛选覆盖完整查询集合，不能只过滤已加载的一页。权限和租户条件不可由客户端搜索条件覆盖。 |
| 查询状态 | MUST 让分页、排序、搜索、筛选使用同一份查询状态；条件改变后按已接受规则回到有效起点，返回列表恢复既定条件。重复参数转换、隐藏默认筛选和请求/显示不一致需有用例。 |
| 异步结果 | MUST 区分加载、成功空态和失败；快速切换条件时旧响应不得覆盖新条件。复用项目取消/序列化机制，不固定等待若干秒后凭截图判断成功。文案和交互采用已接受 UI 合同。 |
| 写后查询 | MUST 定义新增、编辑、删除及状态变更后的刷新/缓存失效；删除末页最后一条后回到有效页，不用伪造成功数据掩盖失败。 |
| 性能与边界 | MUST 限制查询规模并验证非法分页/排序；SHOULD 结合真实数据量检查索引、慢查询、N+1 和深分页，目标与阈值来自项目，不对所有项目硬套同一耗时。 |

分页/返回字段与默认容量引用 [接口与数据](interfaces-and-data.md) 及项目原生 API authority；
本标准不另定一份返回 envelope。高精度 ID、日期时区、精度和 null 语义也由该 owner 决定。

组合页面的空态 MUST 按当前查询下所有应展示的独立分区判断；一个分组为空不能证明整个
页面为空。验收 SHOULD 包含仅次要分区有内容、各区均空、搜索无匹配及清空恢复；分区是否
参与搜索、是否隐藏及部分失败如何呈现仍由项目 Product 决定，不新增通用占位或反馈。

## Details and return paths

- 业务对象列表 MUST 提供可定位到该对象的详情；详情可采用项目已接受的页面、抽屉或展开区，
  不强制为每个列表新建路由。应覆盖必要业务字段及适用的关系、状态、操作信息。
- 详情 MUST 使用稳定对象身份并独立校验访问范围；列表缓存不能自动成为完整详情或授权来源。
  深链/刷新适用时，MUST 在不依赖上一次列表内存的情况下读取。
- MUST 覆盖对象不存在、已删除、无权限、加载失败、状态已变化和返回列表；具体展示方式来自
  当前 Product/UI。不存在与无权限是否区分由项目的信息披露规则决定。
- 详情与列表共享的字段/枚举/状态 MUST 来自同一语义 owner；截断文字、临时行对象和猜测
  的字段映射不能成为第二套事实源。只读列表同样适用详情默认要求。
- 字母索引、页内目录和局部展开 MUST 区分视图定位与产品导航。按已接受的返回合同验证
  操作后的 URL、历史栈和一次返回目的地；点击成功或内容滚到可见位置不足以证明返回正确。
  项目明确需要可分享锚点或锚点历史时保留该行为，不一律禁止 URL hash。

## State and action rules

Product MUST 在现有 Feature 中定义适用的 `状态 × 动作 × 角色/数据范围`；每项至少说明
前置条件、允许/禁止、成功后的状态与数据影响、冲突/失败后的结果。无需枚举不存在的角色
或组合；测试要覆盖每条实际拒绝规则及关键转换。

以采用“启用/停用”生命周期的可删除配置为默认场景：启用状态禁止删除，停用后仍需检查
权限和引用关系。若业务另有生命周期，MUST 由 Product owner 明确其规则，不能仅按字段名
猜测；归档、取消、关闭、撤回和删除也不能互换。

| 层 | 必须承担的责任 |
| --- | --- |
| UI | MUST 按当前状态与权限呈现已接受的可用动作、隐藏/禁用及提交中行为；复用统一权限/状态能力，不在各按钮重新定义业务规则。 |
| API / application service | MUST 在每次请求验证身份、对象/租户范围、当前状态与业务前置条件；绕过按钮直接请求同样拒绝。拒绝不能产生成功副作用。 |
| Data / external effects | MUST 按风险使用项目已有事务、条件更新、版本校验、约束及幂等设施，防止检查后状态变化仍提交。外部动作无法与事务原子完成时，复用已采用的补偿/可靠事件方案。 |
| Verification | MUST 覆盖合法转换、非法转换、越权、过期页面/并发冲突，以及重复提交适用时的最终副作用；仅按钮禁用或 HTTP 退出码不足以证明正确。 |

禁用/隐藏是产品交互；服务端拒绝是业务约束，两者都要满足各自合同。是否新增确认框、
失败提示或重试按钮由已接受 Product/UI 决定，不从防误操作要求自动推导新界面。

写请求结果未知时，MUST 用原操作身份保留防重状态，并按已接受的接口合同回查。
锁定范围只覆盖该操作及受影响对象的冲突动作；共用抽屉、路由或状态容器不扩大锁定范围。
存在共享状态或可切换入口时，验收 MUST 在原结果仍未知时按真实入口发起下一笔独立操作，
核对独立操作可填写、按合同正常发出请求，且原操作未重复提交；再按既定的成功和失败回查
结果核对锁定范围及释放。已确认的业务级互斥按其原合同验证。

服务端 MUST 持有身份、授权、对象范围和业务资格的最终判定。客户端 MUST NOT 用本地
用户资料、缓存字段（如登录名、工号或用户编码）或推测的角色、状态代替服务端决定，
也不得据此新增隐藏、置灰或提前返回。对已建立登录会话的操作，若表单和请求合同的
必需输入齐备，即使本地用户资料为空、迟到或过期，也 MUST 通过统一请求层正常提交，
由服务端校验。已确认的必填和格式校验、重复提交保护、正式会话失效处理，以及按服务端
明确返回的状态或能力执行的已确认界面规则继续适用。合同要求的字段确实缺失时，MUST
沿用项目约定的来源和失败行为，禁止猜值、伪造身份或擅自新增资格判断。

变更涉及此边界时，MUST 用现有测试入口验证「会话有效、请求字段齐备、本地资料未就绪」
仍发出符合合同的请求，并核对服务端拒绝经由
[已确认的反馈行为](ui-components-and-tokens.md#accepted-product-feedback)处理。
服务端拒绝路径须验证未产生成功副作用。Mock 可证明客户端请求和反馈行为，服务端
实际校验及副作用须单独取证。只移除提示或只断言按钮状态不足以关闭此类缺陷。

## Reuse before implementation

**已有适用 owner 时 MUST 复用，禁止业务切片自行另建同职责实现。** 实现前只读检查
相邻调用方、公共入口、测试和项目采用记录；不能只搜索一个相似文件名就判定不存在。

| 能力 | 首先定位的项目 owner |
| --- | --- |
| 前端请求与鉴权 | 统一请求 client、API adapter、错误/刷新/取消规则、凭据注入边界 |
| 列表与页面 | 公共分页/表格/搜索组件、查询状态、列表详情模式、路由与缓存 owner |
| 表单与 UI | 表单校验、提交状态、权限控件、上传、字典、日期/金额格式、组件 public import 与 token |
| 后端基础能力 | 统一返回、异常映射、参数校验、分页/排序、认证与数据权限、中间件 |
| 业务与数据 | 当前状态规则 service、事务、并发/幂等、查询仓库、迁移、审计/事件 producer |
| 工程与测试 | 现有工具链、生成源、原生合同、测试 seam、fixture owner、日志与追踪入口 |

复用决定写入现有技术设计、Task 或 handoff：能力、owner/public entry 引用、代表调用方、
`reuse / extend / new` 及理由。Product 只保存用户行为，不承载 import 路径。

- `reuse`：满足当前行为，直接消费公共入口，禁止绕过统一请求/返回/权限层。
- `extend`：同一 owner 有确定缺口，在授权范围内扩展，并检查实际消费者；不能复制到页面
  内打补丁。跨模块兼容冲突遵循 [任务与实现](tasks-and-implementation.md)。
- `new`：已说明检索范围且不存在合适 owner，或 owner 明确接受独立职责；必须给出边界、
  消费者和验证。不得为了“统一”把不同业务硬塞进万能组件、万能 service 或重复 DTO。

“复用”不等于保留已知缺陷；它要求修复归属正确。第三方依赖中的公共类型应先查实际 import
和版本合同，不能因仓内找不到定义就重写一份。默认格式也不能覆盖已有系统的原生合同。

## Other recurring scenarios

只选择当前切片实际触发的行；各行细节写回原 owner，不默认增加功能。

| 场景 | 必须明确的决定 | 关键验证 |
| --- | --- | --- |
| 新增/编辑表单 | 必填、长度、格式、业务唯一性、服务端校验、取消/提交语义、已有值加载 | 非法值、重复提交、失败后数据、过期编辑冲突；客户端校验不替代服务端 |
| 删除/归档 | 生命周期、引用关系、数据保留、允许范围与后续查询 | 被引用/启用/越权拒绝，成功后详情/列表一致；软删除不是自动默认 |
| 批量操作 | 选择范围、跨页语义、逐项权限与状态、全成或部分成功、重试单位 | 混合可操作/不可操作集合，失败项身份和最终副作用 |
| 导入/导出 | 格式/容量、逐行校验、数据权限、敏感字段、异步进度/结果适用性 | 坏行/大文件/重复、导出范围、注入风险、失败结果；不默认导出全部数据 |
| 上传/下载 | 类型/大小/授权、存储 owner、可访问生命周期 | 非法内容、越权访问、取消/失败、清理；不将客户端文件名当可信路径 |
| 关联/级联选择 | 关系 owner、上级变化时下级清理、不可见/失效关联 | 切换/清空/无权限/慢响应、保存后再读；不以列表首项补造目标 |
| 权限与多租户 | 操作权限、对象范围、字段披露、切换身份后的缓存边界 | 直接 API 请求、跨租户 ID、旧缓存/旧页面；每次请求检查 |
| 金额/时间/标识 | 精度、舍入、单位、时区/区间端点、序列化边界 | 大整数 ID、零/空/null、跨日、往返序列化；不转 Number 破坏身份 |
| 异步任务/通知 | 启动与完成的区别、幂等/取消、超时、失败与结果回读 | 重复触发、完成前退出、迟到结果、结果未知；不把提交成功当业务完成 |
| 多端与热更新 | 每端适用功能、包/服务/账号/数据身份、原生能力 | H5/Android/Harmony 及模拟器/真机分开记结论；专项包不代表完整工作区 |

安全要求引用 [安全与隐私](security-and-privacy.md)，UI 采用和反馈引用
[UI Components and Design Tokens](ui-components-and-tokens.md)，异步状态实现引用
[Code Design](code-design.md#asynchronous-state-and-cached-consumers)。

## Acceptance and handoff

需求→API/UI/技术设计→实现→测试→审查 MUST 引用同一组适用场景及项目决定。已有
Requirement/Task/Result/Evidence 承载这些引用；不额外创建场景账本、状态机或 schema。

| 阶段 | 当前 owner 交接内容 |
| --- | --- |
| Product | 适用场景、例外/未决、列表/详情行为、状态动作规则和可观察验收 |
| API / UI / architecture | 原生合同引用、查询/状态/失败语义、公共能力与复用决定；只完成适用 lane |
| Implementation | 当前依据、实际复用/扩展、新增理由、变更范围、影响的原验收项 |
| Verification / Review | 逐项消费相同依据，核对正常/拒绝/边界/并发及实际层级，返回原验收项的缺口 |

列表最小业务链为 `查询 → 排序/分页 → 详情 → 返回`；有写入授权时再选择一条
`合法操作 → 回读` 以及对应拒绝路径。只测可达、空列表、Mock 或按钮状态不能宣称链路通过。

复用旧证据 MUST 核对相同验收项、平台、源/包/热更新身份、环境、账号角色、数据与断言；
改变后只重验受影响部分，首次失败与更正均保留。异步缺陷记录输入、请求参数、响应时间
和稳定页面结果；新旧版本使用相同条件。未知副作用先回读，禁止盲目重放。

按 [证据标准](evidence.md) 分开报告源码、自动化、Mock、真实接口、浏览器/设备和业务
终态；可复用结果写回项目现有唯一验收账，不以用例数、入口数或代理终态替代业务完成度。
