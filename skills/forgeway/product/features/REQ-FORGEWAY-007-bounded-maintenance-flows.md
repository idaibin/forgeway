# In-context cleanup and instruction improvement

## Accepted behavior

During ordinary development, the implementation owner removes only proven obsolete
code made unnecessary by the accepted change. Review verifies deletion/consumer
evidence without editing source; verification checks preserved behavior. Instruction
gaps produce a scoped proposal for their owner, not automatic rule edits. Professional
Skills remain self-contained and usable without Forgeway.

Separate requests such as “清理这里的死代码” or “精简这份 AGENTS” select the
[cleanup](../../workflows/dead-code-cleanup.md) or
[instruction](../../workflows/instruction-optimization.md) workflow directly from
SKILL.md. Resolve scope and acceptance from context; ask only for decisive missing
inputs. Defaults remain audit/analysis; explicit fix/apply requests retain their scoped
authority. Comparison is an optional explicit outcome requiring budget, quality oracle
and isolation. Reuse existing Task/Result/Observation contracts and host capabilities.

## Acceptance

Ordinary development/review/tests need no separate form or experiment. Separate
requests reach their corresponding workflow without a prompt wrapper. Retain unknown
consumers, accept an empty proven set, reject instruction quality regressions and
preserve unrelated local work. Document/distribution checks do not establish host
selection or execution; use fixed live cases and report installed/multi-host evidence
separately.
